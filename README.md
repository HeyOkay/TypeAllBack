# LayoutPreview

## Журнал ввода

В событиях «Ввод» отображаются физический номер `tN`, символ, ожидаемый текст
сессии и подсказка в скобках. Пробел — `␠`, Enter — `↵`, Backspace — `⌫`.
«Подтверждение» показывает текст, прочитанный из редактора, а «Подсказка» —
фактически вычисленный вариант. Пока расчёт для нового текста не выполнен,
журнал пишет об этом явно. Он не запускает дополнительный расчёт эвристики.

Строка окончания содержит последний отслеженный ввод, подтверждённый и ожидаемый
текст; при переходе из обработки клавиши указан также номер вызвавшего его
события. Фильтр «Только ввод и границы сессий» скрывает служебные проверки.
Вся история, включая текст ввода, остаётся в памяти и ограничена 200 событиями.

## Журнал событий

Журнал позволяет выделять текст мышью и копировать через **Ctrl+C**.
**Ctrl+A** при фокусе в журнале выделяет весь его текст. Пока журнал в фокусе,
его отображение не обновляется, чтобы не сбрасывать выделение; утилита продолжает
работать. После перехода в другое поле журнал догоняет события.

Ярко-зелёным выделено начало текущей сессии, ярко-красным — её окончание.
Начало новой сессии приглушает оба цвета предыдущей: старые начала остаются
зелёными, окончания — красными. Остальные события имеют обычный цвет.

## Правила начала сессии

В окне отладки есть отдельный раскрытый список **«Правила начала сессии»**.
Каждая строка имеет свой переключатель и пояснение:

1. **Ввод при готовом поле** — первый подходящий символ без выделения.
2. **Ввод вместо выделенного текста** — первый символ, заменяющий выделение.
3. **Ввод до готовности поля** — первые клавиши до получения снимка, затем
   обязательное подтверждение всей захваченной последовательности.

Все три включены по умолчанию. Можно отключить каждое по отдельности или все
сразу. Изменения действуют без перезапуска, завершают активную сессию с явной
причиной и очищают ожидающий ввод. Настройки хранятся в памяти до перезапуска.
Клавиши, захваченные до изменения настройки, не могут начать новую сессию.
Переключение не отключает проверки безопасности замены.

## M1.1 — отладочное окно сессии

Окно открывается при запуске, не забирая фокус. Оно показывает подтверждённый
редактором текст, ожидаемый текст с учётом очереди клавиш, предполагаемую замену,
диапазон и начало сессии, раскладки, счётчик слов и причины окончания. После
завершения сохраняется ожидаемый текст последней сессии. В истории — последние
200 событий и этапы принятия с причинами отказа.

- `Ctrl+Alt+F12` — скрыть / показать окно; крестик только скрывает его.
- «Пауза просмотра» останавливает обновление окна, но не утилиту.
- «Очистить историю» удаляет сохранённые события и последнюю завершённую сессию,
  не прерывая текущую.
- `--no-debug-window` — начать со скрытым окном.
- Текст отладки хранится только в памяти, на диск автоматически не записывается.
- Лимит 10 слов и реакция на ручную смену раскладки остаются для следующего этапа.
  Счётчик слов пока только диагностический; переключатели начала уже доступны.

При неполной замене проверьте, входит ли оставшийся текст в «Ожидаемый текст»,
и есть ли перед принятием событие окончания и начала новой сессии. Если диапазон
полный, причины отказа и этапы backend помогут отделить сбой записи от обрыва
сессии. Отсутствие причины отказа также является результатом для дальнейшей отладки.

## Историческое описание прототипа v0.5


Первый настоящий Windows vertical slice для проверки идеи поверх обычного Блокнота. Это уже не HTML-макет.

## Что проверяем

- глобально видим физические нажатия EN/RU;
- показываем WPF overlay рядом с настоящим caret;
- overlay не должен забирать focus у Блокнота;
- `Ghb` -> `При`, `Ghbdtn` -> `Привет`;
- Right Arrow при видимом preview принимает вариант;
- клик по preview тоже принимает вариант;
- Accept удаляет отслеживаемое ошибочное слово, вставляет Unicode-вариант и просит foreground window переключиться на принятую раскладку;
- после Accept следующие физические клавиши должны уже печататься в новой Windows-раскладке;
- Ctrl/Alt/Win shortcuts не перехватываются.

## Что поставить

1. VS Code.
2. .NET 10 SDK x64.
   Проект таргетит `net10.0-windows` (LTS).
3. В VS Code расширение **C# Dev Kit** (`ms-dotnettools.csdevkit`). VS Code сам предложит его из `.vscode/extensions.json`.

## Запуск

1. Распакуй папку проекта.
2. В VS Code: **File -> Open Folder...** и выбери `LayoutPreviewNative-v0.5`.
3. Дождись, пока C# Dev Kit загрузит проект.
4. Нажми **F5**.
5. Если VS Code спросит конфигурацию, выбери **LayoutPreview — Debug**.
6. Открой обычный Windows Notepad и выполняй `TEST-CHECKLIST.md`.
7. Остановить prototype: **Shift+F5**.

В Debug Console VS Code появляются строки `[LayoutPreview] Started`, `Preview: ...`, `Accept: ...` — они пригодятся, если overlay не появляется или Accept ломается.

## Архитектура v0.5

- `LayoutPreviewController.cs` — keyboard hook, session tracking, conversion, Accept.
- `PreviewWindow.xaml/.cs` — focus-safe WPF overlay.
- `Native.cs` — Win32 interop.
- `.vscode/launch.json` — F5 debug.
- `.vscode/tasks.json` — build перед запуском.

## Важно

Это специально маленький proof of concept. Пока не пытаемся поддержать все приложения. Сначала добиваем цепочку **Notepad -> caret -> preview -> Accept -> Replace -> Switch Layout**. После этого добавляем persistent session/segments, UI Automation/TSF caret/text context, Chromium/Electron и protected contexts.

Исходники подготовлены вне Windows. Здесь можно проверить структуру проекта и конфиги, но WPF/Win32 runtime должен быть фактически скомпилирован и прогнан на твоём Windows 11 через F5. Первый Windows compile/runtime feedback будет частью следующей итерации.

## Что изменено в v0.5

- Координаты caret больше не передаются в WPF `Left/Top` как будто это DIPs: overlay позиционируется через `SetWindowPos` в тех же физических пикселях, что и Win32 caret. Это исправляет сильный уезд preview при Windows scaling.
- Preview выравнивается по вертикальному центру реального `rcCaret`, а не через магическое `y - 7`.
- Accept больше не анимирует `Window.Left`. Окно остаётся неподвижным, а preview двигается внутри него через `TranslateTransform` — это заметно снижает рывки layered WPF window.
- Fade теперь идёт от реальной opacity 1.0 к 0 и заканчивается к 50% движения; раньше прозрачность дублировалась альфой цветов + opacity контейнера и растворение было почти незаметно.
- Для WPF-анимаций явно запрошено 60 FPS.
