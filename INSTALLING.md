# TypeAllBack 0.1.2

Предварительная версия для Windows 10/11 x64. MSI устанавливает приложение только для текущего пользователя в `%LOCALAPPDATA%\Programs\TypeAllBack` и создаёт ярлык в меню «Пуск». .NET включён в пакет.

## Установка

1. Выйдите из запущенной утилиты через меню трея.
2. Откройте `TypeAllBack-0.1.2-win-x64.msi` и дождитесь завершения установки.
3. Запустите TypeAllBack из меню «Пуск».

Настройки в `%LOCALAPPDATA%\TypeAllBack\settings.json` сохраняются. Если автозапуск TypeAllBack уже включён, установщик переносит запись на установленный EXE; если выключен, не включает его. Отладка открывается из трея или Ctrl+Alt+F12.

## Обновление и удаление

Последующие пакеты используют постоянный UpgradeCode, более высокую версию MSI и стабильные GUID компонентов. Старые файлы заменяются в транзакции Windows Installer. Более старую версию поставить поверх новой нельзя. Настройки вне каталога программы не заменяются и не удаляются.

Удаление доступно в установленных приложениях Windows; собственная запись автозапуска очищается. Перед удалением выйдите из утилиты через трей. Заданный пользователем другой путь в записи автозапуска приложение не удаляет.

Источник обновлений — GitHub Releases HeyOkay/TypeAllBack. После выбора обновления приложение скачивает MSI, сверяет SHA-256 и размер, закрывается, устанавливает обновление без ручного открытия MSI и запускается снова. В 0.1.0 этот механизм отсутствует, поэтому переход на 0.1.2 требует однократной установки MSI.

## Сборка

В репозитории:

```powershell
.\Tools\build-release.ps1 -ProductVersion 0.1.2
.\Tools\verify-installer.ps1 -MsiPath .\artifacts\installer-0.1.2\TypeAllBack-0.1.2-win-x64.msi
```

Нужен .NET 10 SDK и доступ к NuGet при первом восстановлении .NET runtime и WiX SDK 5.0.2. Никакие инструменты глобально не устанавливаются. Пакет находится в `artifacts/installer-0.1.2`, автономная сборка — в `artifacts/publish-0.1.2`. Эти файлы и сгенерированный список компонентов не входят в Git.

## Выполненная проверка

Сборки Debug/Release, 592 регрессионные проверки, запуск автономного EXE с недоступным внешним DOTNET_ROOT, метаданные имени/версии, сохранение существующего settings.json. MSI проходит ICE-валидацию; ICE91 отдельно исключён как предупреждение о возможной установке в per-machine режиме, который этот пакет не поддерживает. Отдельно проверены таблицы MSI: per-user область, runtime, UpgradeCode/последовательность обновления, отсутствие settings.json и удаления пользовательских файлов.

Фактическая установка, обновление с предыдущего MSI и удаление пока не выполнялись; это следующий пользовательский чек.
